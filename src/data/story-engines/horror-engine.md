1. ENGINE NAME
============================================================

Horror Story Engine

Internal engine identifier:
horror

============================================================
2. PURPOSE
============================================================

The Horror Story Engine is a dedicated story-generation engine for
original horror, suspense, mystery, paranormal, supernatural,
revenge, curse, hidden-secret, injustice, and consequence-based stories.

Its purpose is to generate high-retention horror stories using the
established Horror Story Engine DNA without flattening the logic into
a generic story prompt.

Core principle:

MYSTERY + FEAR + EMOTION + INFORMATION

The engine must make horror events perform story work. A supernatural
event should normally reveal a clue, establish a rule, increase danger,
expose history, develop a character, or move the story toward the
climax.

============================================================
6. STORY STRUCTURE / STORY BEATS
============================================================

A strong Horror Story Engine story normally follows:

BEAT 1 — NORMAL WORLD
Establish the protagonist, location, situation, or ordinary life.

BEAT 2 — UNUSUAL SIGN
Introduce something that feels wrong but is not fully explained.

BEAT 3 — HORROR SIGNATURE
Introduce the story's distinctive recurring horror element.

BEAT 4 — FIRST WARNING
The protagonist receives a warning, strange message, impossible
sound, visual sign, dream, or unexplained event.

BEAT 5 — FIRST INCIDENT
A concrete supernatural or threatening event occurs.

BEAT 6 — CONSEQUENCE
The incident changes the situation.

BEAT 7 — SECOND INCIDENT
The horror returns, but it must add new information or increase danger.

BEAT 8 — PATTERN DISCOVERY
The protagonist begins connecting clues.

BEAT 9 — TARGETING
The protagonist becomes personally connected to the horror.

BEAT 10 — INVESTIGATION
Characters search for the reason behind the events.

BEAT 11 — HIDDEN PAST
A historical event, secret, crime, death, betrayal, injustice, or
buried truth is revealed.

BEAT 12 — ORIGIN OF HORROR
The story explains how the supernatural presence came to exist.

BEAT 13 — MOTIVE
The ghost/entity's emotional reason becomes understandable.

BEAT 14 — TARGET RULE
The story establishes why the current protagonist is being targeted.

BEAT 15 — TWIST / REVELATION
A new piece of information changes the audience's understanding.

BEAT 16 — CLIMAX
The protagonist directly confronts the source, truth, curse, ghost,
entity, or consequence.

BEAT 17 — CONSEQUENCE
The hidden truth produces a meaningful result.

BEAT 18 — EMOTIONAL RESOLUTION
The central emotional conflict is resolved, released, punished, exposed,
or transformed.

BEAT 19 — FINAL HORROR AFTERTASTE
Optional final supernatural detail that leaves controlled lingering fear.

8. HOOK SYSTEM
============================================================

Primary hook formula:

EXACT TIME
+
ISOLATED LOCATION
+
IMPOSSIBLE EVENT
+
VISUAL / AUDITORY EVIDENCE
+
QUESTION

Example pattern:

"हर रात 12:13 बजे बंद पड़े कुएं से एक बच्चे के रोने की आवाज आती थी।
लेकिन गांव में उस उम्र का कोई बच्चा था ही नहीं।"

The hook should create immediate questions.

The engine should prefer:
- Exact time
- Strange location
- Impossible event
- Specific sensory detail
- Immediate unanswered question

Avoid generic openings such as:
"एक गांव में एक भूत रहता था..."

The hook should feel like the beginning of an actual incident.

============================================================
9. SUSPENSE / RETENTION SYSTEM
============================================================

Core suspense sequence:

STRANGE
→ POSSIBLE
→ SUSPICIOUS
→ EVIDENCE
→ PATTERN
→ CONFIRMATION
→ THREAT
→ PERSONAL THREAT
→ CONFRONTATION

Fear/relief cycle:

FEAR
→ RELIEF
→ CONTRADICTION
→ NEW FEAR

A false relief should normally be meaningful.

When the audience thinks the problem is over, introduce a logically
connected contradiction or new clue.

Question chain:

1. What happened?
2. Why did it happen?
3. Who/what is responsible?
4. Why now?
5. Why this location?
6. Why this person?
7. What does it want?
8. Can it be stopped, released, exposed, or resolved?

Each major reveal should answer at least one question while creating
another useful question.

Important:
Mystery must increase curiosity, not confusion.

============================================================
10. CHARACTER SYSTEM
============================================================

Characters must have narrative purpose.

Core roles may include:
- Protagonist
- Victim
- Witness
- Investigator
- Informant
- Guilty participant
- Family member
- Watchman / caretaker
- Authority figure
- Supernatural entity

Not every role is required.

The protagonist should have a meaningful connection to the mystery.

The target reason must be understandable.

The ghost/entity should, when appropriate, have:

1. Identity
2. Origin
3. Motive
4. Horror signature
5. Target rule
6. Trigger
7. Limitation or rule, when useful

Avoid unnecessary characters.

============================================================
11. DIALOGUE RULES
============================================================

Dialogue should carry a large portion of the story.

The engine should prefer dialogue over unnecessary exposition.

Dialogue should:
- Reveal clues
- Create suspicion
- Show fear
- Establish relationships
- Reveal hidden information
- Create conflict
- Advance investigation
- Deliver warnings
- Increase tension
- Support the climax

Avoid long artificial speeches unless the scene specifically requires it.

Characters should speak according to their role and situation.

Questions and answers can be used to reveal information naturally.

Dialogue must not become a disguised exposition dump.

============================================================
12. NARRATION RULES
============================================================

Narration should be purposeful and controlled.

Use narration for:
- Setting
- Time
- Atmosphere
- Transitions
- Physical action
- Suspense
- Information that cannot naturally be delivered through dialogue

The user prefers more voice/dialogue and less unnecessary narration.

Narration should not repeatedly describe the same fear.

============================================================
13. OUTPUT FORMATTING RULES
============================================================

For character dialogue:

CHARACTER NAME
Dialogue

For narration:

नैरेटर
Narration

The character name must be on its own line.

The spoken dialogue must appear directly below the character name.

Narration label must be on its own line.

Do not add emotion tags.

Do not add unnecessary formatting that was not requested.

Do not provide a separate copy option unless the user explicitly asks
for a copy option.

============================================================
14. TWIST / REVEAL SYSTEM
============================================================

Twists must be connected to previously planted information.

A valid twist should:
- Reinterpret earlier clues
- Reveal a hidden connection
- Change the target logic
- Reveal a hidden participant
- Expose the real reason behind the haunting
- Connect the protagonist to the past
- Reveal that an apparently supernatural event had a deeper human cause
- Or deepen the supernatural mystery without breaking internal logic

Do not use random twists that contradict established rules.

The twist should feel surprising in the moment but understandable in
retrospect.

============================================================
15. CLIMAX SYSTEM
============================================================

The climax should pay off the central mystery.

Possible climax resolutions:
- Truth exposed
- Ghost confronted
- Curse broken
- Victim released
- Guilty person exposed
- Justice/consequence occurs
- Protagonist escapes with a cost
- Supernatural rule is completed
- Emotional resolution occurs
- The horror continues in a controlled final beat

The climax should not introduce an unrelated problem.

============================================================
16. ENDING SYSTEM
============================================================

The ending should resolve the story's central emotional or mystery
question.

Possible ending types:
- Release
- Justice
- Consequence
- Revenge completed
- Truth exposed
- Curse ended
- Sacrifice
- Escape with a cost
- Supernatural continuation
- Final horror aftertaste

Optional final horror aftertaste:

A final sound, object, message, footprint, record, phone call, voice,
shadow, location detail, or impossible event can imply that the horror
is not completely gone.

The final beat should be connected to the story's established logic.

17. HORROR-SPECIFIC RULES
============================================================

17.1 UNIQUE HORROR SIGNATURE

Every story should have a distinctive recurring horror element.

Examples from reference mechanics:
- Wet footprints
- Orange boiler suit
- Radio/static
- Doli
- Four men
- Band music
- Cemetery
- Empty railway station
- Train horn
- Child crying from a well

These examples are mechanics/signatures, not events to copy.

17.2 SIGNATURE EVOLUTION

A recurring signature should evolve:

SIGNATURE
→ WARNING
→ EVIDENCE
→ HISTORY
→ MEANING
→ CLIMAX

Do not repeat the exact same scare without new information.

17.3 EVIDENCE LADDER

Strange
→ Possible
→ Suspicious
→ Evidence
→ Pattern
→ Confirmation

17.4 HORROR ESCALATION

Unusual
→ Uncomfortable
→ Suspicious
→ Impossible
→ Threatening
→ Personal
→ Confrontational

17.5 HUMAN-TO-SUPERNATURAL CAUSALITY

A preferred structure:

Human wrongdoing/tragedy
→ Death/loss
→ Unresolved emotion
→ Supernatural return
→ Strange sign
→ Target selection
→ Consequence

This is not mandatory for every horror subtype, but it is a major
engine behavior.

17.6 LOCATION MEMORY

A location can function as a story character:

LOCATION
→ HISTORICAL EVENT
→ RESIDUAL SIGNATURE
→ PRESENT HAUNTING

17.7 IMPOSSIBLE COMMUNICATION

Possible pattern:

Normal communication
→ Impossible detail
→ Confusion
→ Realization
→ Fear

Examples of mechanics:
- Radio from an impossible location
- Phone call from someone who should not be calling
- Message from a dead person
- Voice from inside a sealed room

If used, the anomaly must have a coherent narrative payoff.

17.8 FALSE DREAM / PREMONITION

Possible pattern:

Dream
→ Supernatural preview
→ Wake-up
→ False relief
→ Real-world confirmation
→ Actual horror

If a dream mechanic is used, it should pay off later.

17.9 INJUSTICE HORROR MODULE

Possible pattern:

Hope
→ Unfair treatment
→ Emotional collapse
→ Death
→ Unresolved grievance
→ Supernatural return
→ Target selection
→ Confrontation
→ Justice / Revenge / Release / Consequence

17.10 TARGET RULE

The story should establish why the protagonist is targeted.

Possible rules:
- Family connection
- Location connection
- Previous action
- Hidden identity
- Inherited secret
- Guilty association
- Accidental discovery
- Broken supernatural rule

Do not randomly target the protagonist without explanation.

- Implied violence
- Shadows
- Sounds
- Footsteps

- Graphic gore

Important:

19. ORIGINALITY / ANTI-COPY RULES
============================================================

Reference stories are used to extract mechanics, not to reproduce
their events.

The engine must not:
- Copy characters
- Copy names
- Copy locations
- Copy exact supernatural events
- Copy dialogue
- Copy distinctive sequences
- Copy the exact plot
- Copy the exact twist
- Copy the exact ending

It may reuse abstract mechanics such as:
- Evidence ladder
- Hidden past
- Haunted location
- Injustice causing supernatural return
- Recurring signature
- Investigation
- False relief
- Impossible communication

The final story must be independently constructed.

============================================================

If the user specifies a length, follow it.

Possible conceptual levels:

SHORT
- Fast hook
- Limited characters
- Compact investigation
- Fewer escalation cycles
- Direct climax
- Short ending

MEDIUM
- Full mystery development
- Multiple evidence points
- Investigation
- Backstory
- Twist
- Climax
- Ending

LONG
- More developed character relationships
- More evidence stages
- Multiple investigation steps
- Deeper hidden past
- More developed supernatural rules
- Larger climax
- Stronger emotional resolution

If no length is supplied, choose a natural length that allows the
central mystery and climax to be properly resolved.

Do not stretch the story with repetitive scares.

22. EDIT / REGENERATE BEHAVIOR
============================================================

When the user asks to edit an existing story:
- Preserve the established engine behavior.
- Modify only what the user requests unless the request requires
  related changes for continuity.
- Preserve formatting.
- Preserve the central horror logic unless the user asks to change it.

When the user asks to regenerate:
- Generate a genuinely different story construction.
- Do not merely replace names or surface details.
- Preserve the requested topic and engine behavior.
- Change scenes, clues, progression, characters, reveal mechanics,
  and/or ending as appropriate.

When the user requests a specific change:
- Do not redesign the entire engine.
- Apply the requested change within the existing logic.

24. HIDDEN / IMPORTANT RULES THAT MUST NOT BE LOST
============================================================

1. Do not turn the engine into a generic horror prompt.

2. Horror events must perform narrative work.

3. Every major recurrence should add information, change the stakes,
   establish a rule, or move the story forward.

4. Mystery must come before full explanation.

5. Do not explain the supernatural origin too early.

6. The audience should understand the ghost/entity's emotional motive
   when the story requires one.

7. The target reason must be meaningful.

8. The central horror signature should evolve.

9. False relief should have a purpose.

10. A dream must have a payoff if used.

11. Impossible communication must have a coherent payoff if used.

12. Backstory should preferably be revealed through clues, investigation,
    witnesses, records, objects, memories, or other story-integrated
    methods rather than a completely disconnected exposition dump.

13. Recurring scares must not become repetitive filler.

14. Internal story logic is mandatory.

15. The ending must pay off the central mystery or emotional conflict.

16. A final horror aftertaste is optional, not mandatory.

17. Human wrongdoing can be the cause of supernatural horror, but the
    engine can also support other supernatural structures.

18. The engine should use empathy-to-fear progression when appropriate:

    VICTIM SUFFERING
    → AUDIENCE EMPATHY
    → SUPERNATURAL RETURN
    → AUDIENCE FEAR

19. Location can carry memory and history.

20. Auditory horror is an important tool.

21. Dialogue should carry significant story information.

22. Narration should remain purposeful.

23. Avoid unnecessary graphic violence.

24. Learn mechanics from references, not surface details.

31. MERGE REQUIREMENTS
============================================================

This section is mandatory when integrating the Horror Story Engine with
the separate Moral Story Engine.

RULE 1 — KEEP BOTH ENGINES SEPARATE

Do not rewrite either engine into a generic shared prompt.

Use:

STORY GENERATOR
→ ENGINE ROUTER
→ HORROR STORY ENGINE

or:

STORY GENERATOR
→ ENGINE ROUTER
→ MORAL STORY ENGINE

RULE 2 — HORROR LOGIC MUST REMAIN INTACT

The following must not be removed:

- Hook system
- Mystery-first behavior
- Horror signature
- Evidence ladder
- Suspense escalation
- Fear/relief cycle
- Investigation
- Hidden past
- Supernatural origin
- Motive
- Target rule
- Injustice module
- False dream module
- Impossible communication module
- Location memory module
- Twist system
- Climax system
- Consequence system
- Final horror aftertaste
- Dialogue-heavy behavior
- Controlled narration
- Originality rules
- YouTube-conscious safety rules
- Output formatting

RULE 3 — SHARED INPUT LAYER IS ALLOWED

A unified interface can collect:
- Story Type
- Topic
- Language
- Length
- User-specific constraints

But once the engine is selected, generation must use that engine's
own rules.

RULE 4 — SHARED OUTPUT LAYER IS ALLOWED

Both engines may return a common story result object, but the content
generation remains engine-specific.

Conceptual structure:

{
  "engine": "horror",
  "story": "...",
  "language": "...",
  "length": "...",
  "metadata": {
    "horror_signature": "...",
    "story_mode": "...",
    "target_rule": "..."
  }
}

Metadata is optional and must not change the visible story format
unless the product explicitly requires it.

RULE 5 — DO NOT FLATTEN

Do not reduce the Horror Story Engine to:

"Write a scary story about [topic]."

That would destroy the engine's unique behavior.

RULE 6 — DO NOT IMPORT MORAL LOGIC INTO HORROR UNLESS NATURAL

A horror story may contain a moral consequence or injustice, but it
must remain a Horror Story Engine story.

RULE 7 — DO NOT IMPORT HORROR LOGIC INTO MORAL STORIES

The Moral Story Engine must retain its own existing logic.

RULE 8 — FORMATTING CONSISTENCY

The unified Story Generator may use the Horror output formatter when
Horror is selected.

RULE 9 — REGENERATION

Regenerate must call the selected engine again.

It must not switch engines or use a generic fallback prompt.

RULE 10 — EDITING

Edits must preserve the selected engine unless the user explicitly
changes Story Type.
